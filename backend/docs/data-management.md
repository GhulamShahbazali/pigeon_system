# Backend — Data Management (Prisma, migrations, seeding, test DB)

> How the database is organized, changed safely, seeded, and tested. Schema contract (tables) lives in `../../docs/technical/schema/` — this is the *mechanics*.

---

## Prisma file organization
```
prisma/
├── schema.prisma          ← generated by hand from docs/technical/schema/*
├── migrations/            ← committed, ordered, never edited after apply
└── seed/
    ├── index.ts           ← runs all seeders
    ├── countries.seed.ts  ← §2 reference
    └── languages.seed.ts  ← §2 reference (ur/hi/ar/en, is_rtl)
```
Generate the Prisma schema **from the section docs** — one model per table, matching types/indexes/cascades. If the doc and schema disagree, the **doc wins** — fix the Prisma model.

## Migration safety
- `prisma migrate dev` **locally only** (it can reset the DB — never on Aiven).
- Shared/staging/prod: `prisma migrate deploy` (applies pending, no reset). The dev script **warns** on a pending migration; applying it is a deliberate act.
- A migration that drops/renames a column referenced by running code is a two-step: add → backfill → switch reads → drop (never a single breaking migration on a live DB).
- Migrations are committed and ordered; **never edit an applied migration** — add a new one.

## Denormalized data integrity
- Counters (`like_count`, `follower_count`, `view_count`) and **averages** (`avg_seconds`, `overall_avg_seconds`) are denormalized. They are updated **inside the write transaction** (never a trigger, never a lagging job).
- The `denorm-counter-recompute` cron (nightly) **self-heals** any drift. On-demand recompute hooks fire on flight insert/edit/delete.
- `duration_seconds` is computed **once on insert** from `release_at`; if `fly_time`/`release_at` is edited, affected flights' durations + averages are recomputed in that transaction.

## Reference-data seeding
`countries` + `languages` are idempotent upserts (`ON CONFLICT DO NOTHING`/upsert) keyed by ISO code, versioned so re-running the seed is safe. Served with an ETag (`reference_data:etag:{table}`).

## Indexes
Create every index the schema docs list (FKs, sort columns, the `(tournament_id, overall_avg_seconds DESC)` standings index, partial `WHERE deleted_at IS NULL` / `WHERE status='live'`, GIN FTS). Verify with `EXPLAIN` that hot reads (standings, feed, inbox, live-now) are index scans.

## Connection pooling (Aiven)
Prisma pool is per process; with ~20 Aiven connections and 4 processes, set `connection_limit` small in `DATABASE_URL` (see `environment.md`). Migrations also consume a connection — leave headroom.

## Test DB lifecycle
- A separate `TEST_DATABASE_URL` (local Docker Postgres or a dedicated Aiven db).
- Repository/integration tests run against a real schema (migrate deploy on a fresh db), wrapped in a transaction rolled back per test, or truncated between tests.
- Domain use-case unit tests use in-memory fakes of the repository interfaces — no DB.
